## Caveats (harness)

- **Lane log contamination, both runs.** The sandbox HOME did not hide the real state dir. Each run found it by absolute path and read the archived `gh39.handoffs.jsonl`, which holds the round-1 and round-2 findings by class. The role's Output rule (reuse a tag from the lane's `handoffs.jsonl`) points it there.
  - The old run read the log before its probes. Its `vendored-reproduction-drift` block matches the round-2 finding, so it is likely seeded by the log.
  - The new run read the log after its `just check`, and it says it reused an existing class.
  - The bias runs toward repeating the logged blocks, which is against item 7's expectation. So the new reviewer's drop to 1 block is a conservative result.
  - A clean future replay needs filesystem isolation (a separate user or a mount namespace), not just a sandbox HOME.
- **No Herdr or GitHub writes.** Both runs tried `herdr-say --parent` 3 times (exit 64, no parent) and then the director fallback. The fallback failed with exit 127 (`herdr` not found), and the sandbox state dir had no `director.toml`. Nothing reached any pane. Both made one unauthenticated read-only GitHub API request for issue #41, and both got 404, so no ticket body. `gh` was unauthenticated.
- The new run's `just check-vendored` with a cold cache fetched from the network inside the sandbox HOME cache. That is the gate's own behaviour (the subject of its block), not a setup the reviewer built.
