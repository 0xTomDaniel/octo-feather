Comms, escalation and lane state

docs / specs / comms.spec.html

How agents talk, how problems go up the chain, and the plain files that hold each lane's state. Agents hand off through Herdr messages; there is no workflow engine, inbox or daemon (ADR 0003).

User stories

As the owner, I hear only from the director, so asks reach me filtered and in context instead of fragmented from every agent.

As a supervisor, a worker that follows a wrong habit cannot type into another lane or straight to the director while its supervisor is reachable.

As the owner, a lane never stalls silently: a worker that ends without reporting is noticed, recovered and reported up.

As the director, I read every lane's current state and history, findings included, from plain files, so I can audit lanes and count repeated finding classes without asking each supervisor.

As the director, I read the whole factory in one report built only from what already records it, so I answer the owner from facts, waits on the owner included, instead of reading each lane's panes.

As the owner, the factory reviews each closed lane and the director's own work, routes what it finds to where the work is written, and sharpens its own questions when a gap slips past them, so I am no longer the one who catches what it missed.

Acceptance criteria

Given an implementer in workspace gh12, When it sends a message to the supervisor of gh13, Then the message is refused, nothing is typed in gh13, and the implementer is told it may message only its parent, proven by an integration test: no screen shows it.

Given an implementer finishing its ticket, When it sends its result to its parent, Then its supervisor's tab shows the result as a message from that implementer.

Given a worker whose supervisor's pane closed before it reports, needs an induced failure: the supervisor pane closes, When the worker finishes, Then the director's tab shows the worker's result, and the worker's tab shows it idle, no longer sending.

Given a supervisor waiting on a worker that ends without reporting, needs an induced failure: the worker's session exits mid-ticket, When the supervisor's goal next checks in, Then the director's tab shows a message from the supervisor naming that worker as ended without reporting and the worker started in its place.

Given a parked supervisor whose lane workspace still holds one of its workers' tabs, When the director sends it a message, Then Herdr shows the supervisor resumed in a new tab of that same workspace, and the message it receives names its new pane.

Given a supervisor whose pull request merged, When it closes the lane, Then the director's tab shows the supervisor's close report while the supervisor's worktree still exists, and the worktree is gone only after the director removes it.

Given an implementer blocked by a scope conflict its supervisor cannot settle, When the conflict reaches the owner, Then it arrives from the director, naming what is blocked, what was tried, and the options.

Given a supervisor delivering several tickets, When a ticket changes state, then the director opens that ticket in the target's tracker, Then the tracker shows the ticket's new state, and the lane record holds no ticket entry.

Given a supervisor that receives a code-review verdict with two findings, When it consumes the verdict, Then the lane's hand-off log gains one finding line per finding, each naming its source, class and whether it blocks, proven by an integration test: no screen shows it.

Given a supervisor whose pull request merged, When it closes the lane, Then the lanes directory no longer lists the lane and its archive holds the lane's record and hand-off log unchanged, proven by an integration test: no screen shows it.

Given the director with three open lanes, one with an implementer working, one escalated to the director and one whose merge ask awaits the owner, When the director runs the factory report, Then the report shows each lane with its pull request and its checks, each agent in its workspace with its Herdr state, and what it waits on: the implementer, the director, and the owner's merge gate with the time it was asked.

Given the director with one lane whose merge ask awaits the owner and another whose spec review awaits the owner's Accept, When the director runs the factory report, Then the report's owner queue lists both, oldest first, each with its lane, its gate and how long it has waited.

Given the director with an open lane that has had two review rounds and recorded model spend, some of it of unknown cost, When the director runs the factory report, Then the report shows that lane's wall time since it started, its two review rounds, and its spend in dollars with the calls of unknown cost counted apart.

Given the director with an open lane whose pull request and main each have a recorded gate run, When the director runs the factory report, Then the report shows the wall time of the lane's last gate run beside main's last.

Given the director whose log holds owner-caught findings of two classes, one of them twice, When the director runs the factory report, Then the report lists each owner-caught class with its count, two for the repeated one, and when it was last seen.

Given the director with open lanes on two target repositories, When the director runs the factory report, Then each lane shows the pull request and checks from its own repository.

Given the director with open lanes while GitHub cannot be reached, needs an induced failure: GitHub unreachable, When the director runs the factory report, Then the report shows every lane from its files and names GitHub as unread with the reason.

Given a supervisor whose lane on a target repository merged and whose workers are closed, When it runs the lane reflection, Then the lane's hand-off log gains one reflection line and one finding line per gap the reflector found, each naming source reflection, its class, the question it answers and where its fix goes.

Given a merged lane whose director log records the director finding one of its workers stranded at a prompt by reading its pane, When its supervisor runs the lane reflection, Then the lane's hand-off log gains a reflection finding naming that catch by hand and what would have caught it first.

Given a supervisor closing a merged lane that has not reflected, When it archives the lane, Then the archive is refused naming the lane reflection as the fix, and the lanes directory still lists the lane.

Given the director whose log holds an owner-caught finding since its last reflection, When the director runs the director reflection, Then the director log gains one reflection line and a reflection finding naming what the owner had to catch and what would have caught it first.

Given lanes whose hand-off logs hold code-review findings of one class in three lanes, When the director runs the director reflection, Then the director log gains a reflection finding for that class with its count, routed to the role, skill, template or structure where the work is written, not to review.

Given a lane whose reflection found no gap in a rule that a code review of a later lane then found broken, When the director runs the director reflection, Then the director log gains a finding of class reflection-missed naming the question to add to the question list or reword.

Given the director whose last reflection was two days ago, When the director runs the factory report, Then the report shows when the director last reflected.

Modular boundaries

The Herdr wrappers (herdr-spawn, herdr-say, herdr-close, herdr-wake) own placing, messaging, parking, resuming and closing agents. Caller-facing seam: each wrapper's arguments, exit status, and printed pane= and workspace= lines. Dependency direction: external-provider; they depend on the Herdr CLI. Roles and skills depend on the wrappers, never the reverse. Observable scope: Herdr workspaces, tabs and agents.

The kit owns the lane record, hand-off log and director log formats; roles write them at the named moments. Caller-facing seam: the files in the Herdr session's state directory, printed by octo-feather-state. Dependency direction: self-contained; readers follow the format, the factory report and reflection among them. Observable scope: file contents and the lane's workspace membership.

The factory report, octo-feather-lane report, owns pulling the factory's current state together for the director. Caller-facing seam: the command and the report it prints. Dependency direction: external-provider; it reads the lane files, the director log, the spend ledger, the gate run trend, Herdr's agent list and GitHub; it writes nothing, and nothing depends on it. Observable scope: the printed report.

Reflection, octo-feather-lane reflect, owns running a fresh reflector over a lane or the director and appending what it returns. Caller-facing seam: the command, the question list, and the reflection and finding lines it appends. Dependency direction: external-provider; it reads the lane files, the director log, the factory report, the agents' transcripts and the question list, and starts the reflector through pi-role; it writes only to the log of what it reflected on. Observable scope: the appended lines.

Every report goes to its recipient through herdr-say; text left in the sender's own pane is not reported. A sender ends its turn after sending instead of polling for a reply; the reply arrives as a new message, and Herdr reports the sender done. Each supervisor runs under a goal for its lane; at each check-in it reads the Herdr state of every worker it waits on, consumes a finished result left on a worker's pane, otherwise recovers or restarts the worker, and tells the director which worker ended without reporting and what it did.

Waiting agents hold no memory: the director parks a supervisor idle at an owner gate, waiting on another lane or held back for load; a supervisor parks a worker it would otherwise keep idle through a long wait. A message to a parked agent resumes it under the same name with its conversation intact; a parked agent is resumed, never relaunched fresh. A parked supervisor resumes in its lane's workspace when that workspace still exists, and in a new lane workspace otherwise. The message that resumes an agent tells it it was resumed and names its new pane.

Lane state

Each Herdr session has its own state directory holding lanes/ (each lane's record, hand-off log and archive/) and the director's director.toml and director log. An agent sees and acts only on lanes of its own session.

One TOML file per open lane, named after the supervisor agent. The director creates it at launch; only the supervisor updates it in place.

The record holds no ticket state: tickets live in the target's tracker only.

The record lists no workers: a lane's workers are the agents in its workspace other than the supervisor, with role and ticket read from their names.

When the director audits lanes it reads every record and writes none: a record is stale when its waiting_on names no listed lane, its supervisor pane is neither live nor named by the latest parked line, or its goal no longer names the lane's scope; the director wakes that supervisor to fix it.

Workspaces and teardown

A lane's workspace id is the prefix of its supervisor's pane id, so no record key holds it. That workspace is the lane's own when no other lane's supervisor and not the director carries the same prefix.

At teardown the director closes a lane's own workspace with herdr-close, which stops every process started in it. A lane started in a shared workspace ends at its supervisor tab, and the close report names that tab, never the workspace. A supervisor sends its close report while its own worktree still exists and never removes that worktree: the director removes it after closing the lane's workspace or tab.

Spec Chat's review service may run in another Herdr session, so each review row carries an owner value naming its session and pane; a review hand-off wakes that pane in its own session.

A just recipe in the kit registers herdr-wake as Spec Chat's wake provider on the remote, so a review hand-off wakes the parked pane its row names.

Risk: whether Herdr keeps workspace and pane ids across a Herdr server restart is unproven; if not, a restart breaks every lane record's supervisor pane.

Factory report

octo-feather-lane report prints the current state of every open lane in the session for the director, who runs it before each status answer to the owner. It reads only what already records that state and collects nothing new: the lane records and hand-off logs, the director log, the spend ledger, the gate run trend, Herdr's agent list, and each lane's pull request in the repository its record names. It writes nothing.

The report prints facts with their times, never a verdict: no lane is called healthy, stuck or late. A source it cannot read is named with the reason, and everything else still prints.

An owner gate is pending when its latest gate line in the hand-off log is asked with no later answered line for the same gate. The owner queue lists every pending owner gate across lanes, oldest first, with its lane, gate and age.

The report counts the director log's finding lines whose class starts owner-caught- by class, each with its count and the time it was last seen, so the owner sees whether what the factory missed declines over time.

The report shows when the director last reflected, from the director log's latest reflection line, or that it never has.

Reflection

A reflection is a fresh reflector (roles #role-reflector) reading what a lane or the director did and answering the question list, so the factory catches its own gaps instead of the owner. octo-feather-lane reflect starts it headless and appends what it returns; the reflector itself changes nothing.

Lane reflection: at close, after the merge and the last worker close and before the archive, the supervisor runs octo-feather-lane reflect <lane>. The reflector reads the lane's record and hand-off log, findings and workarounds included, the factory report's numbers for the lane, the director log's lines about the lane, and the transcripts of the lane's supervisor, its workers and the director, which hold the owner conversation. The archive refuses a lane whose hand-off log has no reflection line and names the reflect command as the fix.

Director reflection: the director runs octo-feather-lane reflect --director after each merge it relays, and whenever the factory report shows its last one more than a day old. The reflector reads the director log, the director's transcript, the factory report and every lane's hand-off log, archived ones included.

In the director reflection the reflect command counts finding classes across every lane's hand-off log, archived ones included, by source and frequency. The reflector routes each class seen two or more times to where the work is written: the role, skill, template or structure that would stop the writer making it, not only more review.

The questions live once, as data in the kit: one list, each question with an id, the reflection it belongs to (lane or director) and its text. Every reflection answers each question of its kind, and each gap it finds gives one finding line. Each kind asks what anything caught after an earlier reflection covered it: that gap is a finding of class reflection-missed against reflection itself, naming the question to add or reword, and the correction lane it starts changes the list (issue-lifecycle #lanes-correction).

Findings go to the log of what was reflected on: a lane reflection's to the lane's hand-off log, the director reflection's to the director log, as finding lines with source reflection, its class, the question it answers, its route (where the fix goes) and a summary citing its evidence, so the repeat count treats them like any other finding. A reflection's class never starts owner-caught-: the director logs what the owner caught. Each run also writes one reflection line, with findings or none.
