Comms, escalation and lane state

docs / specs / comms.spec.html

How agents talk, how problems go up the chain, and the plain files that hold each lane's state. Agents hand off through Herdr messages; there is no workflow engine, inbox or daemon (ADR 0003).

User stories

As the owner, I hear from the factory only through the director, so asks reach me filtered and in context instead of fragmented from every agent.

As the owner, delegated work advances without routine permission requests, while decisions I own and reliable completion still reach me.

As a supervisor, a worker that follows a wrong habit cannot type into another lane or straight to the director while its supervisor is reachable.

As the owner, a lane never stalls silently: outstanding worker results are accounted for, and required completion and outside-authority blockers reach the parent.

As the director, I read every lane's current state and history, findings included, from plain files, so I can audit lanes and count repeated finding classes without asking each supervisor.

As the director, I read the whole factory in one report built only from what already records it, so I answer the owner from facts, waits on the owner included, instead of reading each lane's panes.

As the owner, the factory reviews each closed lane and the director's own work, routes what it finds to where the work is written, and sharpens its own questions when a gap slips past them, so I am no longer the one who catches what it missed.

Acceptance criteria

Given an implementer in workspace gh12, When it sends a message to the supervisor of gh13, Then the message is refused, nothing is typed in gh13, and the implementer is told it may message only its parent, proven by an integration test: no screen shows it.

Given an implementer finishing its ticket, When it sends its result to its parent, Then its supervisor's tab shows the result as a message from that implementer.

Given a supervisor waiting on a worker that exits mid-ticket without reporting, needs an induced failure: the worker session exits, When the supervisor reconciles its outstanding work, Then an attempt records the unreported ending, partial result and diagnosed recovery; a replacement has a different provider-session identity and no competing writer remains.

Given a supervisor with a fixture to be added containing a recoverable local validation failure and independent ready work within its delegation, When the supervisor assigns the repair then advances the independent work, Then both assignments advance within the lane without a director permission request, and their evidence is retained locally.

Given a supervisor with a fixture to be added containing an owner-held access blocker and independent ready work, When the supervisor escalates the access need then advances the independent work, Then the director receives one actionable access decision naming the blocked branch, attempts and options, while the independent assignment advances.

Given the director with open lanes on two target repositories, When the director runs the factory report, Then each lane shows the pull request and checks from its own repository.

Given the director whose log holds an owner-caught finding since the last director reflection, When a supervisor archives its merged lane, Then the director log gains one reflection line and a reflection finding naming what the owner had to catch and what would have caught it first.

Given the director whose last director reflection ran two days ago, When the director starts a lane, Then the director log gains a new reflection line.

Given lanes whose hand-off logs hold code-review findings of one class in three lanes, When a supervisor archives its merged lane, Then the director log gains a reflection finding for that class with its count, routed to the role, skill, template or structure where the work is written, not to review.

Given a lane whose reflection found no gap in a rule that a code review of a later lane then found broken, When the supervisor of that later lane archives it, Then the director log gains a finding of class reflection-missed naming the question to add to the question list or reword.

Given the director whose log holds owner-caught findings from the last seven days and from the seven days before, When the director runs the factory report, Then the report opens, before any lane, with the owner-caught count for each of those two weeks.

Given the director whose implementers in the last seven days were each offered a skill that only some of them read, and whose code reviewers read a skill their role is not offered, When the director runs the factory report, Then the report shows, for each skill and each role, how many of that role's sessions were offered the skill and how many read it, with the reads of a skill the role was not offered counted apart.

Given a target whose tracker holds an open correction-lane issue for a finding class, When a supervisor archives a merged lane whose logs add a new finding of that class, then another supervisor archives a lane that adds no finding of it, Then the tracker shows no second correction-lane issue for that class and one new comment on the open issue quoting the new finding with its lane, its date and the running count.

Modular boundaries

The Herdr wrappers (herdr-spawn, herdr-say, herdr-close, herdr-wake) own placing, messaging, parking, resuming and closing agents. Caller-facing seam: each wrapper's arguments, exit status, printed pane= and workspace= lines, and the spawn, close and parked lines they append to a hand-off log. Dependency direction: external-provider; they depend on the Herdr CLI. Roles and skills depend on the wrappers, never the reverse. Observable scope: Herdr workspaces, tabs and agents, and the lines they append.

The kit owns the lane record, hand-off log and director log formats; roles write them at the named moments. Caller-facing seam: the files in the Herdr session's state directory, printed by octo-feather-state. Dependency direction: self-contained; readers follow the format, the factory report and reflection among them. Observable scope: file contents and the lane's workspace membership.

The factory report, octo-feather-lane report, owns pulling the factory's current state together for the director. Caller-facing seam: the command and the report it prints. Dependency direction: external-provider; it reads the lane files, the director log, the spend ledger, the gate run trend, Herdr's agent list, the agents' Pi session files and GitHub; it writes nothing, and nothing depends on it. Observable scope: the printed report.

Reflection, octo-feather-lane reflect, owns running a fresh reflector over a lane or the director, appending what it returns, and filing the correction lanes its findings make due. Caller-facing seam: the command, which the archive and lane start run, the question list, the reflection and finding lines it appends, and the correction-lane issues it files. Dependency direction: external-provider; it reads the lane files, the director log, the factory report, the agents' transcripts and the question list, starts the reflector through pi-role, and files issues through the tracker skill; it writes only to the log of what it reflected on and the tracker. Observable scope: the appended lines and the filed issues.

Consume completed artifacts and exhaust actionable owned work before parking. An activity label or pending final gate alone is not a reason to park ready work. Record the exact blocker, authority holder and wake condition in existing parent evidence. The director parks genuinely waiting supervisors and its own general workers; supervisors park their genuinely waiting workers. Lane children use their lane hand-off log; director children use the director log's parked entry. Closing and parking record themselves: each close or park that succeeds appends its own close or parked line, and one that is refused or fails appends none. Shared parked lookup reads both the director log and lane logs, honoring the recorded parent, role, working directory and provider session. Only the same unfinished assignment may resume its conversation; an independent assignment gets a unique name and fresh session as roles requires. A finished assignment's old name is not a destination for new work. A parked supervisor resumes in its lane workspace when it exists, otherwise in a new lane workspace; a general worker resumes in its actual parent's workspace. The resume message names the new pane and the same assignment.

Parent notifications

BLOCKED and DONE are the normal parent outcomes. The event table is the complete parent-notification allowlist, not a report-everything fallback. Routine pilot, smoke and recovered local validation results stay in existing evidence, not messages. The director receives lane milestones, never individual worker or ticket results: a lane's merge ask, its close (reported as issue-lifecycle main moved says), and blockers, gates, spec calls and risks the table routes to it. Notification supplies information; permission is needed only outside durable delegation or at an actual owner gate. Owner acceptance, merge, consequential product/risk, security, immediate spec calls and cross-lane needs retain their own gates.

Routine details and recovery evidence remain in existing lane records, hand-off logs, result files, tracker results and revision-bound artifacts, not a second status store. A lane's result files are archived with its record and hand-off log; a director worker's result file is removed a week after that worker is gone. Recovery is cause-based and bounded by existing runtime and resource constraints. Ordinary task instructions and worker results are not blindly replayed, cancelled or restarted solely because of DONE, timeout or compaction. Existing ADR 0023 runtime terminal stopped-notice retries are the one explicit exception; duplicating a terminal notice differs from replaying executable work or a worker result. Before replacement account for partial commits, uncommitted work and late results, establish a single writer, and verify current assignment and head. A late result is compared with current artifacts before unique findings are reused. No custom inbox, daemon, scheduler or new message protocol is added: a result file is the result itself, which nothing polls or drains.

Lane state

Each Herdr session has its own state directory holding lanes/ (each lane's record, hand-off log, result files and archive/) and the director's director.toml and director log. An agent sees and acts only on lanes of its own session.

One TOML file per open lane, named after the supervisor agent. The director creates it at launch; only the supervisor updates it in place, except its supervisor key, which a supervisor's resume rewrites and the director may correct by hand.

Workspaces and teardown

A lane's workspace id is the prefix of its supervisor's pane id, so no record key holds it. That workspace is the lane's own when no other lane's supervisor and not the director carries the same prefix.

At teardown (when: issue-lifecycle main moved) the lane's post-merge routine, running outside the lane's workspace, closes the lane's own workspace with herdr-close, which stops every process started in it. A lane started in a shared workspace ends at its supervisor tab, never the workspace, and a supervisor tab another open lane's record names stays open, named as kept with that lane. The routine then removes the lane's worktree, unless a live agent outside what it closed still works in it, as a kept supervisor tab's agent may: that worktree stays, named as kept with that agent. The supervisor never removes it. Reporting: issue-lifecycle main moved.

Spec Chat's review service may run in another Herdr session, so each review row carries an owner value naming its session and pane; a review hand-off wakes that pane in its own session.

A just recipe in the kit registers herdr-wake as Spec Chat's wake provider on the remote, so a review hand-off wakes the parked pane its row names.

Risk: whether Herdr keeps workspace and pane ids across a Herdr server restart is unproven; if not, a restart breaks every lane record's supervisor pane.

Factory report

octo-feather-lane report prints the current state of every open lane in the session for the director, who runs it before each status answer to the owner. It reads only what already records that state and collects nothing new: the lane records and hand-off logs, the director log, the spend ledger, the gate run trend, Herdr's agent list, the agents' Pi session files, and each lane's pull request in the repository its record names. It writes nothing.

The report prints facts with their times, never a verdict: no lane is called healthy, stuck or late. A source it cannot read is named with the reason, and everything else still prints.

An owner gate is pending when its latest gate line in the hand-off log is asked with no later answered line for the same gate. The owner queue lists every pending owner gate across lanes, oldest first, with its lane, gate and age.

The report counts the director log's finding lines whose class starts owner-caught- by class, each with its count and the time it was last seen, so the owner sees whether what the factory missed declines over time. It is the factory's headline quality measure: the report opens with the owner-caught count for the last seven days beside the seven days before.

The report shows skill reach, so the owner sees whether the skills each role lists are used in real work: for each skill and each role, over the last seven days, how many of the role's sessions were offered the skill and how many read it. A session is offered a skill its system prompt lists; it reads one when any of its tool calls, a batched one included, reads that skill's SKILL.md. A session that read a skill it was not offered is counted apart, beside the role.

The report shows when the director reflection last ran, from the director log's latest reflection line, or that it never has.

Reflection

A reflection is a fresh reflector (roles #role-reflector) reading what a lane or the director did and answering the question list, so the factory catches its own gaps instead of the owner. When one runs is fixed by the factory's own moments, never chosen by an agent: octo-feather-lane reflect starts it headless and appends what it returns, and the reflector itself changes nothing.

Lane reflection: at close, after the merge and the last worker close, the supervisor's octo-feather-lane archive runs the lane reflection and then the director reflection before it moves any file. The lane's reflector reads the lane's record and hand-off log, findings and workarounds included, the factory report's numbers for the lane, the director log's lines about the lane, and the transcripts of the lane's supervisor, its workers and the director, which hold the owner conversation. When either reflection cannot run, the archive refuses, leaves every file in place and names the reflection that failed.

Director reflection: a fresh reflector reflects on the director's work since the last director reflection. It runs at every lane archive, so after every merge, and when a lane or the director starts while the last one is more than a day old, so at least daily while the factory works. The director neither starts it nor answers its questions; what the director notices on its own it still logs as its own finding lines. The reflector reads the director log, the director's transcript, the factory report and every lane's hand-off log, archived ones included.

In the director reflection the reflect command counts finding classes across every lane's hand-off log, archived ones included, by source and frequency. The reflector routes each class seen two or more times to where the work is written: the role, skill, template or structure that would stop the writer making it, not only more review.

The questions live once, as data in the kit: one list, each question with an id, the reflection it belongs to (lane or director) and its text. Every reflection answers each question of its kind, and each gap it finds gives one finding line. Each kind asks what anything caught after an earlier reflection covered it: that gap is a finding of class reflection-missed against reflection itself, naming the question to add or reword, and the correction lane it makes due changes the list.

Findings go to the log of what was reflected on: a lane reflection's to the lane's hand-off log, the director reflection's to the director log, as finding lines with source reflection, its class, the question it answers, its route (where the fix goes, marked target: when a lane reflection puts the fix in its lane's own repository rather than the kit) and a summary citing its evidence. A reflection's class never starts owner-caught-: the director logs what the owner caught. Each run also writes one reflection line, with findings or none.

After each reflection the reflect command applies the correction-lane rule (issue-lifecycle #lanes-correction) to every finding line, the new ones included, so no agent judges whether a correction lane is due: for each class the rule makes due, and for each reflection-missed finding, it files the correction lane's parent issue in the tracker of the repository that owns the route's artifact, quoting the findings and naming the reflection's route, and prints it: the kit's for a route to the kit's roles, skills, evals, scripts, templates or question list, for a class no reflection routed and for every reflection-missed finding; a target's only for a route a lane reflection of that target marked as its own, quoting only that target's lanes' findings; never a repository whose lane only contributed a finding. A finding logged by a lane of a repository other than the tracker's is quoted, in an issue and a recurrence comment alike, by its lane, date and class only, never its summary, route or evidence, so no repository's text reaches another's tracker. A target route whose lane record names no repository, or one that is no longer that repository's current name or was created after the lane started, is refused, naming the record to fix, and nothing is filed in it. A recurrence is never a new issue: when that tracker holds an open correction-lane issue of the class, reflection-missed included, it files none and adds one comment to that issue quoting each finding no earlier issue text or comment quotes, with the run that found it (lane or director), its date and the class's running count of findings, and prints it; a rerun with no new finding adds nothing. The director starts each filed issue's lane; how filed issues reach it: issue-lifecycle main moved. The correction intake report, octo-feather-lane intake, applies the same rule to every open correction-lane issue, grouped by class with its findings, so the director closes, with that evidence, each one the rule does not make due; it writes nothing. Judgment stays only where no rule can decide: what the reflector finds, and how the corrector fixes it, judged in that lane's review.
