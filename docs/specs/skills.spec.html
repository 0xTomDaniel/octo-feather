Skills and their sources

docs / specs / skills.spec.html

Skills are plain folders in .agents/skills/, the cross-client Agent Skills location (ADR 0018). Skills with an upstream in Matt Pocock's skills or pstack are vendored from it and patched only where a decided ADR needs it.

User stories

As a maintainer, every skill with a Matt or pstack equivalent uses that upstream text plus a small patch, so the kit stays light and picks up upstream fixes.

As a maintainer, every patch says on its first line which decision it serves, so I can tell whether it is still needed.

As the owner, each role loads only the skills its role file lists, so one role's instructions never leak into another.

As the owner, every vendored skill's licence and author is credited, so the kit can be shared.

Acceptance criteria

Given a maintainer, When any change edits the text of a vendored skill, Then the edit lands as a patch in the skill's patch folder whose first line names the ADR it serves, and re-applying the pinned upstream with its patches reproduces the committed skill.

Given a maintainer, When any change adds a skill without a name or description in its frontmatter, Then the gate fails naming the skill.

Given a supervisor in a target repository that has its own skills folder, When it starts an implementer there, Then the implementer has exactly the skills its role file lists available, and none from the target's folder or the kit's by discovery.

Given a box with Spec Chat's skills installed for the user, When the director starts a supervisor, then the supervisor needs a change to its accepted spec, Then the lane's pull request shows that spec change logged as a judgement call by that supervisor, and the supervisor has shaped nothing else.

Given a maintainer, When any change vendors a new upstream skill, Then NOTICE names that skill with its upstream, pin, licence and author.

Modular boundaries

The Skillfile owns which upstream skills are vendored, at which pin, and how patches are kept across updates. Caller-facing seam: Skillfile, Skillfile.lock and .skillfile/patches/skills/<name>/. Dependency direction: external-provider; it depends on the upstream repositories and the skillfile tool. Observable scope: the committed folders in .agents/skills/.

pi-role owns which skills a role gets: discovery off, one load per listed skill, external skills from the target repository's .agents/skills. Caller-facing seam: the role file's skills and externalSkills keys. Dependency direction: self-contained over the kit checkout and the repository's .agents/skills. Observable scope: the skills a started agent reports.

Where skills live and how they load

Every kit skill, vendored or local, is a folder in .agents/skills/; role files stay in agents/.

A role has exactly the skills its file lists available: discovery is off for every role, so neither the kit's nor a target repository's .agents/skills loads by itself. A target's own skills reach an implementer only when the target's AGENTS.md declares them on its Repo skills: line and the implementer loads them by name.

Skills installed outside the kit, such as Spec Chat's, are named under externalSkills and found only in the target repository's .agents/skills, the working checkout's and then its main checkout's, never in a home folder (ADR 0013). A target repository gets Spec Chat only as links in its .agents/skills, never as .claude/ or .codex/ links (ADR 0001). The supervisor lists Spec Chat's shaping and review skills, and uses shaping only to make the spec changes its logged calls record (ADR 0021); shaping itself happens in the owner's chat (ADR 0021).

Shaping is not a factory role: just shape, run in the target repository, starts Pi with only the shaping skills: grill-with-docs, improve-codebase-architecture, sharpen and the grilling, domain-modeling and codebase-design skills they call, from the kit, and spec-chat-shape from the target's .agents/skills (ADR 0012, ADR 0021). The kit's AGENTS.md names it in one line.

From pstack the kit vendors correct, principle-prove-it-works, blast-radius and sharpen, and leaves out interrogate, show-me-your-work and swarm.
