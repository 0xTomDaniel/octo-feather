Model spend: one ledger

docs / specs / spend.spec.html

Every model call the kit makes costs money. The kit records each call where it is made, in one ledger, so the owner sees what the factory spent and checks it against the provider's own count.

User stories

As the owner, I see what the factory spent on classifier models by day, by lane, by purpose and by model, from records the kit's own call path wrote, never from what an agent reports.

As the owner, I see whether the ledger's OpenRouter spend matches what OpenRouter counted for the kit's key, and how big any gap is.

As the owner, the agents' own model use sits in the same ledger, so each lane's whole model cost shows by role.

Acceptance criteria

Given a maintainer in no lane who has run a judgment question's bench, When they ask the kit for its spend totals, Then the bench's classifier calls show under the bench purpose and no lane, by day and by model, with their tokens and a cost that matches the cost the bench reported.

Given a supervisor whose lane ran the advisory judge on its pull request, When the supervisor asks the kit for its spend totals, Then the judge's classifier call shows under that lane and the judge purpose, with its model, tokens and cost.

Given the owner with the OpenRouter key the kit's classifiers use, When the owner asks the kit for its spend totals, Then beside the totals, for today, this week and this month, OpenRouter's own count for the key shows next to the ledger's OpenRouter total and the gap between them.

Given a lane whose supervisor, workers and product judge ran, When the owner asks the kit for its spend totals by lane, Then that lane's agent spend shows under each role that ran, beside its classifier spend, with the lane's total.

Modular boundaries

The ledger owns one record per model call: when, lane, purpose, model, tokens and cost. Caller-facing seam: the call paths below append to it at the call; the spend command reads it. Dependency direction: self-contained; it lives in the kit's state and depends on no model. Observable scope: every recorded call, in the order made.

The spend command owns the totals and the reconcile. Caller-facing seam: one kit command anyone on the box runs. Dependency direction: external-provider; it reads the ledger and asks OpenRouter for the key's usage. Observable scope: totals by day, lane, purpose and model, and per window OpenRouter's count, the ledger's OpenRouter total and the gap.

Each kind of call has one writer, the code that makes the call; no agent writes or edits the ledger.

Rules

A call's lane is the lane whose space it runs in, a product judge or factory eval run included; a call made in no lane's space is recorded under no lane.

A call's cost is what the provider reported for it; a call with no reported cost is recorded as unknown, and the totals count those calls apart from the dollars.

The ledger only grows: no record is changed or removed.

A call whose record cannot be written still returns its answer and says on its error output that its spend went unrecorded; the reconcile shows the gap.

The gap is OpenRouter's count minus the ledger's OpenRouter total over the same window; spend on the key the kit did not make, or a call path that missed its record, shows there.

The ledger records and reports; it sets no budget and blocks no call.
