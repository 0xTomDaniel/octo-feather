# Owed evals: issue #63

An owed eval fails before its behaviour change and passes after it; the change's smoke run is in `evidence/` (rule: docs/adr/0008).

- Supervisor, spec calls (issue-lifecycle `#gates-spec-calls`, docs/adr/0021, issue #63): (a) a criterion that fails but can pass as written gets rework, no spec edit and no call; (b) a needed weakening, which is also the lane's fourth call: spec edit, call line and status change in one commit, `herdr-say --parent` to the director at once and work goes on; (c) a relayed denial: the change undone or revised and `denied` set in the same commit; the merge ask and PR body carry `octo-feather-spec-status calls` output. Smoke: `evidence/2026-10-22-spec-call-probes.md` (probes (a), (b)).
- Implementer, corrector and code reviewer, spec calls (issue #63): the implementer and the corrector never edit a spec and ask their supervisor with the change and its evidence; the code reviewer does not block a spec edit that a logged call names (no spec job, owner 2026-10-21). Smoke: `evidence/2026-10-22-spec-call-probes.md` (probes (c), (d), (e)).
- Director, spec calls (issue #63, docs/adr/0020): a supervisor's weakening or fourth-call message reaches the owner at once with the lane still running; an owner denial at merge is relayed as rework and is an owner correction at a gate, so a correction lane starts (spec `#lanes-correction`) whose issue names the call's role. Smoke: `evidence/2026-10-22-spec-call-probes.md` (probe (f)).
