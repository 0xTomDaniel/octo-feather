# Integration and end-to-end tests only

Tests drive public surfaces and never unit-test internals. A public surface is the app CLI with `--json`, HTTP or UI, or, for an integration test, a public library function: one the package offers to callers outside it, such as a function the spec or README names (`build_context()` in pilot 1), never a private helper. End-to-end tests and `just qc` go through the CLI, HTTP or UI. A target with none of the three uses its runnable script (`harness.py` in pilot 1) as its end-to-end and QA path; a target with no runnable script either has no end-to-end test, and its PR says QA does not apply. Each acceptance criterion gets one or two tests, run against the repo's real data files where they exist, so the suite stays small. Nothing only a test uses lives in production code: no test-only flag, env var, hook, parameter or branch; a test reaches a hard state by mocking at the boundary. Agents rewrite internals freely, so tests pinned to internals break on every refactor and prove little about behavior; we accept slower tests and coarser failure location. Decided by Tom, 2026-10-18 and 2026-10-20.

The vendored `tdd` skill is patched to match: before writing any test, the implementer writes down the seams under test, public surfaces only, so every test is integration or end-to-end and never a unit test of internals; it takes them from the ticket's acceptance criteria, one or two tests each, and confirms with the user only seams the ticket does not name. The patch also names the test leak as an anti-pattern. Approved by Tom, 2026-10-18 and 2026-10-20.
