# Every app ships a CLI with --json and a verify skill, and that is what agents and E2E tests drive

Each template exposes the app through its own CLI whose commands print `--json`. Agents verify their work through it, E2E tests call it, and the product judge (`just qc`, until Jev) judges its output; MCP is a thin wrapper added only when a task benefits; which MCP reaches the kit's agents: ADR 0016's Capabilities paragraph. A CLI is the cheapest surface that an owner, a test and an agent can all use the same way, which is pstack create-verification-skill's lesson. Decided by Tom, 2026-10-18.

Each target repository also has one verify skill, `verify-<app>`, in pstack create-verification-skill's shape (Launch, Doctor, Drive, Evidence, Cleanup, Helpers, feature map): the one scripted way the implementer, the qc judge and the corrector drive the real app and keep the evidence, so a pass means someone saw it work. The kit vendors pstack's create-verification-skill and maintain-verification-skill with Pi patches rather than writing its own; templates ship a starting skill; the rules are quality spec `#verify-skill`. Where a UI renders a view model, behaviour is driven through the view model by the CLI or an API and the browser only for what the user sees (quality spec `#acceptance-verify-view-model`): a browser drive is slow, brittle and expensive next to a CLI call, while a view-model app's behaviour is fully reachable without one. Corrected in place by Tom (owner), 2026-10-25 (issue #136), after a spike drove a pstack-generated verify skill under Pi on the box and inside the qc sandbox. The verify skill drives the app through the target's one app-driver contract and writes to its one evidence store: ADR 0025 (corrected in place, 2026-10-26).

## Considered options

- A kit-authored verification skill. Rejected: pstack's already holds the shape and the proof standards; vendoring with patches keeps upstream fixes (skills spec `#acceptance-patch-only`).
- Browser drives for every feature of a UI app. Rejected: for a view-model app they re-prove through the slowest surface what the CLI or API already proves.
