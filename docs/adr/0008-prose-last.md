# The ladder: structure, exact check, structured judgment, prose

Every behavior the kit defines (a duty, a rule, the fix for an agent mistake) sits on the highest rung that can hold it. This ADR is the one statement of the ladder; AGENTS.md, the `correct` patch and the role files point here.

1. **Structure.** Architecture or types make the mistake unwritable: one owner per piece of state, one supported way, internals hidden. A rule is such state: it is stated once, where it is owned (rung 2 names the owners; a term's owner is GLOSSARY.md), and every other file points there (path and section or anchor) instead of restating it; decided by Tom (owner), 2026-10-23 (issue #124).
2. **Exact check.** A check (GLOSSARY.md) rejects it with an error that names the fix. Allowed only when it is exact: the script tests the rule itself, so a case that escapes it is a defect to fix in the script, not a reason to reclassify it. The rule is the one stated where it is owned (a spec criterion, an ADR, a recorded owner ruling), never the check's own docstring or error, or any proxy would turn exact by redefining its rule. When owners conflict, the latest owner ruling wins, and a criterion or ADR outranks a table that only describes the gate. Exact examples: a file exists, a path resolves, a schema field is present, a role's model family differs from another's, a word is banned and the owned rule is the word ban (the retired words, owner ruling 2026-10-22; the lane-branch literal strings, owner's #71 scope). A proxy is never a check: a script that tests a stand-in correlating with the rule, however factual what it reads (code tokens for coupling, words for reachability, a regex over prose for intent, a path convention for a public surface). Failure example: `scripts/check-test-surface` (#104) tested six module-loading tokens in tests/*.sh as a stand-in for "tests reach no internals" (docs/adr/0002); tests coupled in other ways passed it (a sed on the justfile, a rewritten private helper). It was a proxy and was deleted (#118).
3. **Structured judgment.** What no exact check can decide, the producer of the work declares in a field with fixed labels: the reviewer's `Verdict: clear|blocking`, `Check:` (or `Checks: none`) and `Owner:` (or `Owners: none`) lines, the implementer's same check field, the implementer's and corrector's same `Owner:` field (column-0 form and reader scope: the code-review skill's Verdict step, **Report fields**; corrected in place, issues #157 and #160), the `just qc` judge's per-criterion `verdict`, a spec call's `kind`, an evidence file's `Smoke: <path>`. An exact check may test that the field is there, well formed and consistent (a `proxy` line with `Verdict: clear` is refused), never re-derive it from prose. Its truth is judged by review, the `just qc` judge, and an eval case graded on the declared field. A classifier question through Pi codemode `models.classify` belongs on this rung, but it gates nothing until its answers are calibrated against owner labels, never runs inside `just check`, and no agent calls it until agents have codemode (#106).
4. **Prose.** An instruction in a role file or skill, with an example of the failure, only for what no rung above can hold (messaging the wrong pane, skipping a report). Nothing fails when an agent skips it.

**Duties.** A mechanical duty, one where the same inputs always give the same action (teardown order, a review row's slug, a lane-log line), is rung 1, never prose an agent must remember. It sits on the highest of three tiers that fits:

1. **Triggered command.** The event that causes the duty (a merge, an archive, a lane start, a park) runs its command, and no prose names it. Examples: teardown on merge, the main-moved broadcast, reflection on archive.
2. **Skill.** Mechanical work an agent must choose to run, with no event to hook, lives in a skill that holds the script and says when and how to run it; the script drives the CLI. The role at most names the skill, which progressive disclosure loads. Examples: registering a review row, filing a correction lane.
3. **Role prose.** Judgment only: merge order by leverage, what to ask the owner, how to review.

A command an agent must remember to run is half the fix: a duty with an event to hook goes on tier 1. Skills by default. A role or skill line a diff adds or changes that holds a mechanical duty below its tier blocks in review (class: the `code-review` skill's Verdict step) unless the line states why no command or trigger fits. Decided by Tom (owner), 2026-10-28 (issue #269; command and trigger, issue #230).

Who builds what (Test and Check: GLOSSARY.md). The implementer writes product code and its tests, nothing else: no check unless an accepted spec criterion explicitly asks for that repo rule (a lint ratchet, say), and then it builds the check as product code, exact only; a rule it cannot test exactly goes back to its supervisor. The corrector builds checks and other factory hardening, on this ladder, from a repeated mistake or an owner correction (routing: docs/adr/0020). Exact versus proxy (rung 2) classifies every decision that passes or refuses from facts, product commands included (kit commands such as `octo-feather-lane merge-ask` and `ticket`, the install-check pins), and the code reviewer classifies each one a diff adds or changes on a `Check:` line and flags a test that is really a check; this paragraph decides who writes such a decision, not whether it is classified (owner ruling 2026-10-26, issue #191). The kit building itself follows exactly the rules of the kit building a target: a kit command that refuses something (`check-skills` failing on a tracker skill with no script) is product code, built by an implementer and tested through the command; a scan of the kit's own text is a check. Decided by Tom (owner), 2026-10-23 (issue #118).

A clean, protected codebase is how we encourage good behaviour. Any change to a prompt, role file or vendored-skill patch ships with an eval case that fails before the change and passes after it, shaped like scaling-octo-engine's `evals/role-workflows/<case>/` (`cases.json`, `harness.py`, `graders/`), run by `just qa`. Its eval check asks of every role or patch change: "what did this remove, or what incident justifies it?" This follows pstack.

Decided by Tom, 2026-10-18; the eval question by Tom (owner), 2026-10-21 (issue #67); facts only on the check rung by Tom (owner), 2026-10-22 (issue #71), after `scripts/check-owned-rules` needed three rounds of phrase fixes and its meaning rules were deleted; exact (tests the rule itself) versus proxy (tests a stand-in) by Tom (owner), 2026-10-23 (issue #118), after #19/#36 (`check-owned-rules`), #40/#49 (ticket wording), #104 (`check-test-surface`) and #107 (a grader regexing a review's prose) each put a proxy on the check rung; the four rungs as written here by the corrector of #118, a call for the owner at merge.

A case review or the judge misses becomes an eval case in `docs/owed-evals/<issue>.md`, never a new check. Stop rule: if a check needs a round of fixes to its wording patterns, delete it instead of tuning it. Every pull request that adds or changes a check carries the reviewer's `Check:` line for it (or `Checks: none`), and `octo-feather-lane merge-ask` prints those lines for the owner.

Until `just qa` exists, an edit to a prompt, role file or skill patch that changes behaviour ships with a recorded live smoke run in `evidence/` (as `evidence/block3-comms-smoke.md` records a real chain), and its eval case is listed as owed in its issue's file, `docs/owed-evals/<issue>.md` (one file per issue, so lanes never edit the same lines; entries naming no issue in `docs/owed-evals/backlog.md`, issue #80). A path repair or the deletion of a dead trigger changes no behaviour and needs only `check-refs`. Decided by Tom (owner), 2026-10-19.

`just check` checks the presence half of this paragraph on a branch (`scripts/check-behavior-smoke`, correction lane #26): when the branch diff from its merge base changes a role file, a skill's markdown or a skill patch, the same diff adds or modifies an `evidence/*.md` and a `docs/owed-evals/*.md`. Whether the smoke covers the change stays with review. A path is exempt when every commit touching it says `Behaviour-neutral: <reason>` in its message; the check prints each one and the supervisor lists them in the merge ask, so the owner sees every opt-out. When such a path is a role file (`agents/*.md`) or a skill patch, one of those evidence files also holds a `Removed: <text>` line, what the change deleted or the incident that justifies it (the pruning habit, issue #67); the check tests that the line is there, never what it says. Each such path is also named on a `Smoke: <path> ...` line of one of those evidence files (a directory token such as `.agents/skills/<name>/` covers the files under it), so one role's smoke no longer stands in for another's: lanes gh71 (`agents/director.md`, evidence ran only the corrector) and gh67 (`agents/implementer.md`, `agents/corrector.md`, no run) passed the presence check with an unrelated evidence file (correction lane #93). The check reads the path on the line, never the run; whether the named run exercised the path stays with review. Decided by the corrector of #93, 2026-10-22, a call for the owner at merge.

`just check` also checks that the commits a branch adds carry the writer's `Owner:` field in their messages (which commits: `scripts/check-owner-field --help`; the field and who owes it: the `code-review` skill's Verdict step; correction lane #466, after 74 of 254 writer reports on the class's lanes carried none). Presence only: whether the search ran stays with review. A call for the owner at merge.

## Considered options

- annotateanything's rule: fix agent behaviour only in prompts, never with blocking guardrails. Rejected: prose is the rung nothing enforces.
- Fact versus meaning as the test for the check rung. Rejected by the owner (#118): `check-test-surface` read only facts and still tested a stand-in for a coupling rule.
- A proxy on the check rung with patterns tuned until they hold. Rejected: four times (#19/#36, #40/#49, #104, #107) the patterns missed cases or flagged good text, and each round of tuning was another rule nothing could prove.
