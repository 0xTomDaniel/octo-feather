# The ladder: structure, exact check, structured judgment, prose

An agent mistake is fixed on the highest rung that can hold it. This ADR is the one statement of the ladder; AGENTS.md, the `correct` patch and the role files point here.

1. **Structure.** Architecture or types make the mistake unwritable: one owner per piece of state, one supported way, internals hidden.
2. **Exact check.** A lint, `just check` script, test gate or grader rejects it with an error that names the fix. Allowed only when it is exact: the script tests the rule itself (the rule the ADR, spec criterion or finding class it cites states), so a case that escapes it is a defect to fix in the script, not a reason to reclassify it. Exact examples: a file exists, a path resolves, a schema field is present, a role's model family differs from another's, a word is banned and the rule is that the word never appears. A proxy is never a check: a script that tests a stand-in correlating with the rule, however factual what it reads (code tokens for coupling, words for reachability, a regex over prose for intent, a path convention for a public surface). Failure example: `scripts/check-test-surface` (#104) tested six module-loading tokens in tests/*.sh as a stand-in for "tests reach no internals" (docs/adr/0002); tests coupled in other ways passed it (a sed on the justfile, a rewritten private helper). It was a proxy and was deleted (#118).
3. **Structured judgment.** What no exact check can decide, the producer of the work declares in a field with fixed labels: the reviewer's `Verdict: clear|blocking` and `Check: <path>: <rule> | reads: <what> | class: exact|proxy` lines, the `just qc` judge's per-criterion `verdict`, a spec call's `kind`, an evidence file's `Smoke: <path>`. An exact check may test that the field is there, well formed and consistent (a `proxy` line with `Verdict: clear` is refused), never re-derive it from prose. Its truth is judged by review, the `just qc` judge, and an eval case graded on the declared field. A classifier question through Pi codemode `models.classify` belongs on this rung, but it gates nothing until its answers are calibrated against owner labels, never runs inside `just check`, and no agent calls it until agents have codemode (#106).
4. **Prose.** An instruction in a role file or skill, with an example of the failure, only for what no rung above can hold (messaging the wrong pane, skipping a report). Nothing fails when an agent skips it.

A clean, protected codebase is how we encourage good behaviour. Any change to a prompt, role file or vendored-skill patch ships with an eval case that fails before the change and passes after it, shaped like scaling-octo-engine's `evals/role-workflows/<case>/` (`cases.json`, `harness.py`, `graders/`), run by `just qa`. Its eval check asks of every role or patch change: "what did this remove, or what incident justifies it?" This follows pstack.

A case review or the judge misses becomes an eval case in `docs/owed-evals/<issue>.md`, never a new check. Stop rule: if a check needs a round of fixes to its wording patterns, delete it instead of tuning it. Every pull request that adds or changes a check, test gate or grader carries the reviewer's `Check:` line for it (or `Checks: none`), and `octo-feather-lane merge-ask` prints those lines for the owner.

Until `just qa` exists, an edit to a prompt, role file or skill patch that changes behaviour ships with a recorded live smoke run in `evidence/` (as `evidence/block3-comms-smoke.md` records a real chain), and its eval case is listed as owed in its issue's file, `docs/owed-evals/<issue>.md` (one file per issue, so lanes never edit the same lines; entries naming no issue in `docs/owed-evals/backlog.md`, issue #80). A path repair or the deletion of a dead trigger changes no behaviour and needs only `check-refs`. Decided by Tom (owner), 2026-10-19.

`just check` checks the presence half of this paragraph on a branch (`scripts/check-behavior-smoke`, correction lane #26): when the branch diff from its merge base changes a role file, a skill's markdown or a skill patch, the same diff adds or modifies an `evidence/*.md` and a `docs/owed-evals/*.md`. Whether the smoke covers the change stays with review. A path is exempt when every commit touching it says `Behaviour-neutral: <reason>` in its message; the check prints each one and the supervisor lists them in the merge ask, so the owner sees every opt-out. When such a path is a role file (`agents/*.md`) or a skill patch, one of those evidence files also holds a `Removed: <text>` line, what the change deleted or the incident that justifies it (the pruning habit, issue #67); the check tests that the line is there, never what it says. Each such path is also named on a `Smoke: <path> ...` line of one of those evidence files (a directory token such as `.agents/skills/<name>/` covers the files under it), so one role's smoke no longer stands in for another's: lanes gh71 (`agents/director.md`, evidence ran only the corrector) and gh67 (`agents/implementer.md`, `agents/corrector.md`, no run) passed the presence check with an unrelated evidence file (correction lane #93). The check reads the path on the line, never the run; whether the named run exercised the path stays with review. Decided by the corrector of #93, 2026-10-22, a call for the owner at merge.

## Considered options

- annotateanything's rule: fix agent behaviour only in prompts, never with blocking guardrails. Rejected: prose is the rung nothing enforces.
- Fact versus meaning as the test for the check rung. Rejected by the owner (#118): `check-test-surface` read only facts and still tested a stand-in for a coupling rule.
- A proxy on the check rung with patterns tuned until they hold. Rejected: four times (#19/#36, #40/#49, #104, #107) the patterns missed cases or flagged good text, and each round of tuning was another rule nothing could prove.
