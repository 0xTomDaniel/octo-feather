# Prose last: structure, then checks, then Jev, then prompts

An agent mistake is fixed as high on this ladder as it will go: first the codebase's structure and types make it impossible; then lint and `just check` reject it with an error that names the fix; then Jev judges what is fuzzy and in between (does the UI match the spec, does a report answer its question), and until Jev exists code review and the `just qc` judge own that rung; prose in a role file or skill comes last, only for process behaviour nothing above can catch (messaging the wrong pane, skipping a report). A clean, protected codebase is how we encourage good behaviour. Any change to a prompt, role file or vendored-skill patch ships with an eval case that fails before the change and passes after it, shaped like scaling-octo-engine's `evals/role-workflows/<case>/` (`cases.json`, `harness.py`, `graders/`), run by `just qa`. This follows pstack. Decided by Tom, 2026-10-18.

Checks test facts, never meaning. A script may check that something exists, resolves or runs, plus exit codes, SHAs, paths and fields. It may never use a phrase list or regex over prose to decide what the text means. Until Jev exists, those calls go to review or the `just qc` judge. A case they miss becomes a Jev eval in future.md, never a new rule. Stop rule: if a check needs a round of fixes to its wording patterns, delete it instead of tuning it. Decided by Tom (owner), 2026-10-22 (issue #71), after `scripts/check-owned-rules` needed three rounds of phrase fixes; its meaning rules were deleted.

Until `just qa` exists, an edit to a prompt, role file or skill patch that changes behaviour ships with a recorded live smoke run in `evidence/` (as `evidence/block3-comms-smoke.md` records a real chain), and its eval case is listed as owed in `docs/future.md`. A path repair or the deletion of a dead trigger changes no behaviour and needs only `check-refs`. Decided by Tom (owner), 2026-10-19.

`just check` checks the presence half of this paragraph on a branch (`scripts/check-behavior-smoke`, correction lane #26): when the branch diff from its merge base changes a role file, a skill's markdown or a skill patch, the same diff adds or modifies an `evidence/*.md` and changes `docs/future.md`. Whether the smoke covers the change stays with review. A path is exempt when every commit touching it says `Behaviour-neutral: <reason>` in its message; the check prints each one and the supervisor lists them in the merge ask, so the owner sees every opt-out.

## Considered options

- annotateanything's rule: fix agent behaviour only in prompts, never with blocking guardrails. Rejected: prose is the rung nothing enforces.
