# Prose last: structure, then checks, then Jev, then prompts

An agent mistake is fixed as high on this ladder as it will go: first the codebase's structure and types make it impossible; then lint and `just check` reject it with an error that names the fix; then Jev judges what is fuzzy and in between (does the UI match the spec, does a report answer its question); prose in a role file or skill comes last, only for process behaviour nothing above can catch (messaging the wrong pane, skipping a report). A clean, protected codebase is how we encourage good behaviour. Any change to a prompt, role file or vendored-skill patch ships with an eval case that fails before the change and passes after it, shaped like scaling-octo-engine's `evals/role-workflows/<case>/` (`cases.json`, `harness.py`, `graders/`). This follows pstack and rejects annotateanything's rule of fixing agent behaviour only in prompts, never with blocking guardrails. Decided by Tom, 2026-10-18.
