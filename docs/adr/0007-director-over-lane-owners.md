# A director that never edits code, over one supervisor per lane

One director owns the program: it takes kickoffs (ADR 0021), cuts lanes and files each lane's parent issue (ADR 0019), starts one supervisor per lane, handles escalations and brings the owner only gates; it edits no code or spec, and its only repo writes are lane branches and worktrees and the spec PR's generated status file (ADR 0021). Each supervisor spawns its implementers and a fresh code reviewer, and integrates with `just integrate` (ADR 0017). Tom: "we MUST have the director... stands in for the owner. I expect this take home to have several issues ongoing in parallel", 2026-10-18.

Every lane gets a supervisor, even when it is the only one running: a fixed rule beats a judgment the director can get wrong, at the cost of one extra context per lane. Workers run `just check` and must be green before they report, but never review or accept their own work: the supervisor spawns a fresh code reviewer, from a different model family than the implementer, for every merge, and Matt's `implement` step that calls `code-review` in the worker's own context is patched out. Approved by Tom, 2026-10-18.

The merge: after the owner says merge, the director relays the yes to the lane's supervisor with the head the merge ask named, and the supervisor alone merges, pinned to that head (`gh pr merge <N> --merge --match-head-commit <head>`). Main moving does not move the head; only a push to the lane branch does. If the only commits since the merge ask are merges of main that resolved no conflict (the lane's own diff against main unchanged) and required checks pass on the new head, the supervisor merges pinned to the new head, with no new `just qc` and no new merge ask, and its done report names both heads (spec `#gates-merge`). Any other change (a fix commit, a rebase, a resolved conflict) or a failed merge is never forced: the supervisor reruns its gates (`just check`, `just qc` on every affected criterion, a fresh code review on the new head) and sends a new merge ask. Merging main in is preferred to a rebase, which rewrites the approved commits. The director then checks main's CI. At close the supervisor sends its close report while its own worktree still exists and never removes it; the director closes the lane's workspace or tab, then removes that worktree (a supervisor that removed its own lost its working directory and never reported).
