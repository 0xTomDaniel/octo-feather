# Owner-accepted revisions preserve built results

An owner accepting a revised spec is a different authority from a supervisor logging a necessary implementation call. Resetting all criteria on owner revision destroys the PR and evidence history, while treating that revision as supervisor calls misrepresents who approved it. This decision supersedes ADR 0021 only where its fresh-spec initialization and immutable baseline wording would apply to a separately owner-accepted revision; the supervisor-call workflow remains unchanged. The contract lives in issue-lifecycle spec [#spec-revisions](../specs/issue-lifecycle.spec.html#spec-revisions), with read-only draft validation at [#revision-draft-check](../specs/issue-lifecycle.spec.html#revision-draft-check).

Requiring the repaired initializer before its own accepted amendment could be delivered would make the repair depend on itself. The owner approved the narrowly scoped sequencing exception at [#revision-repair-sequence](../specs/issue-lifecycle.spec.html#revision-repair-sequence), rather than manual status reconstruction, invented supervisor calls or a separate spec. Acceptance before implementation and the normal quality and merge gates remain; this is not a general exemption from spec-first delivery.
