# Matt's workflow skills are model-invoked

mattpocock/skills marks its workflow skills `disable-model-invocation: true`, so only a slash command can start them. In octo-feather the agents run the workflow, so each vendored one that carries the flag (implement, implement-spec, to-tickets, grill-with-docs, improve-codebase-architecture, and pstack's correct, principle-prove-it-works, blast-radius, sharpen, principle-encode-lessons-in-structure and principle-build-the-lever) gets a patch line removing it. They are vendored at exact pins through the `Skillfile` (mattpocock/skills@49dd158, cursor/plugins@0b8e952), with patches in `.skillfile/patches/skills/<name>/` whose first line names the reason; each patch changes only what an ADR needs. The shaper role (`agents/shaper.md`, started by `just shape`) lists all the shaping skills: grill-with-docs, improve-codebase-architecture and sharpen, and the grilling, domain-modeling and codebase-design skills they call. Shaping happens outside the factory (ADR 0021), so no factory role loads them. The implementer and the `just qc` judge get principle-prove-it-works; the implementer gets blast-radius; the corrector gets principle-encode-lessons-in-structure and writing-for-agents; principle-encode-lessons-in-structure also goes to the director, supervisor and implementer, and principle-build-the-lever to the director, supervisor and corrector (issue #269). handoff, to-spec and triage are not vendored, because nothing uses them. Upstream's "call the Skill tool" wording is kept: Pi models load the named skill. Pollution is contained because every role loads only the skills its role file lists (ADR 0016).
