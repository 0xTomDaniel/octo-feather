# Until Jev, `just qc` is a fresh cross-family judge that runs each claimed criterion

`just qc STATUS PR ID...` (`scripts/octo-feather-qc`) is the product judge until Jev replaces it. In the lane worktree, at the integrated head, it starts a fresh code reviewer headless (`pi-role agents/code-reviewer.md -p`, ADR 0016; `openai/gpt-6.1-sol` high, read-only tools) with its own QC brief: judge the whole lane head against every criterion the lane claims (the ids given, their text read from the spec), find and run each criterion's demo path through the app's public surface (ADR 0009), and report one pass or fail per criterion with the command it ran and the output. The script, not the judge, then writes the status file (ADR 0021): each passed criterion becomes `built` with the lane's PR, each failed one stays `planned`, and only that file is committed. The judge's model family must differ from the implementer's, and the script refuses one that does not; it also refuses a dirty worktree, a report that does not name exactly the claimed ids, and a judge that changed the worktree. It is never part of `just check`. Decided by Tom (owner), 2026-10-19.

The judge has bash, so it runs sandboxed by default (#33; lane #15 run 6 showed an env or PATH shim is not isolation: an explicit `herdr --session default` read the live session). `octo-feather-qc` starts `scripts/octo-feather-qc-sandbox` in two namespaces. The outer `unshare -rm` (root of a private user and mount namespace) sets the boundary up: a private `/tmp`; tmpfs over the Herdr and gh config dirs, `~/.ssh` and the cache dir, `/dev/null` over git credential files; a scratch state dir where the caller's archived lanes and director log are read-only history and live lane records (`lanes/`, `sessions/`, `director.toml`) are masked; Pi's agent dir a tmpfs with its files bound back read-only (`models.json` included) and `auth.json` a per-run copy on the hidden run tmpfs. Then every other mount but `/proc` is remounted read-only (`/dev/mqueue` and `/sys` included; the judge also gets its own IPC namespace), and the lane worktree is mounted as an overlayfs over the real one, its upper and work dirs on a run tmpfs that is then masked from the judge. The judge has no persistent writable path: everything it writes, anywhere (worktree, ignored or not, `.git`, `/tmp`, cache, Herdr dir), dies with the namespace; the git common dir outside the worktree stays read-only. There is no exception, Pi's `auth.json` included (round 4, finding persistent-credential-copies: the original bound writable let the judge store a copied token under a new key). `octo-feather-qc` snapshots the box's `auth.json` in memory at run start; after the judge exits, outside its namespaces, the sandbox sends the copy back over a pipe if it changed, and `octo-feather-qc` writes it to the box only when the box file is still byte-identical to the snapshot (compare and swap: another Pi may have refreshed meanwhile) and the copy is a token refresh in place (the same nested keys, none added or removed, the same value types, every changed value a string or number of at most 4x its old length, 64 bytes minimum, and 8 KiB); the write is atomic (temp file, same mode, rename). The compare and the write both happen while holding Pi's own auth lock (proper-lockfile's `<auth.json>.lock` directory, taken by mkdir, waited for up to about 10 s and never stolen, not even when stale; not obtained: discarded as `refused:auth-locked`), so a concurrent Pi refresh is never clobbered (round 6, finding non-atomic-auth-writeback). Anything else is discarded. The report and a `qc: cleanup:` line record `auth_writeback: none|written|refused:<reason>`, the reason naming no key or value. The judge itself runs in a nested user namespace mapped to the caller's uid and gid (not root), with its own mount and PID namespace and `no_new_privs` (`unshare --map-user --map-group --mount --pid --fork --kill-child`, `setpriv --no-new-privs`): it holds no capabilities and every inherited mount is locked, so `umount` of a mask fails, also after the judge's own `unshare -rm` (round 2, finding reversible-sandbox-masks). PID 1 of that namespace is ours: it starts the one fresh per-run Herdr server (`qc-<head12>-<runid>`) inside it, so panes the judge spawns inherit the whole sandbox, pinned by a `herdr` shim that drops `--session`/`--remote`/`--machine`; no GitHub or git credentials and no parent route (`OCTO_FEATHER_PARENT`, `HERDR_*` ids and socket paths). Before the judge starts PID 1 prints one ok or FAIL line per check (no capabilities, masks locked, HOME read-only (and the kit, unless the kit is the judged worktree, as when it judges itself), worktree overlay, writable persistent paths: none (no exception), Herdr, creds, route, state, history, worktree clean), and any FAIL aborts (exit 66). After the judge exits it counts the agents the judge started (headless Pi and sandbox Herdr panes), stops and deletes the sandbox session, kills and counts every other process in the PID namespace, and exits, so the kernel kills anything left there or in a nested PID namespace (`unshare -m env -u HERDR_SESSION ...` cannot escape). Proof, cleanup record and judge stderr come back to `octo-feather-qc` over pipes, so no write fd pins a mount being remounted read-only. Credential copies are prevented by construction, not scanned for (round 3, finding persistent-credential-copies: a scan of pre and post values cannot cover an intermediate one), so the credential content scan is dropped. The read-only check survives: after the judge exits, the sandbox, outside the judge's namespaces, lists the overlay upper dir, and `octo-feather-qc` fails the run (exit 3, the paths in the report) on a new, changed or deleted tracked file or an untracked file git does not ignore; ignored outputs and `.git` writes are discarded silently, and the real worktree never changes. `--no-sandbox` is for debugging only: printed as UNSANDBOXED, it writes the report and never changes the status file. Decided by Tom (owner), 2026-10-19.

The judge gets read-only GitHub evidence (#34; lane #23 failed 8 criteria only because GitHub was absent). When the worktree's `origin` is a GitHub URL (read locally, so missing auth cannot pass for no remote), `octo-feather-qc` runs `scripts/octo-feather-qc-ghsnap` before every run, outside the sandbox and with the caller's gh auth, into fresh per-run scratch: issue, PR and workflow run lists (all states; 500, 500, 200), full views (comments, reviews, commits, files, closing issues, sub-issues, blocked-by, timeline, the head's check runs) for the 200 most recently updated issues and PRs, fetched in parallel (about 12 s for this kit's 35), and the repo, branches, labels and origin refs; older items stay list-only and are named. The snapshot is made read-only, bound read-only into the sandbox, and removed after the run. `scripts/qc-bin` goes first on the judge's PATH: its offline `gh` answers `gh issue view|list`, `gh pr view|list|diff|checks`, `gh run view|list`, `gh repo view` and `gh api` GETs (with `--json` and `-q/--jq`) from the snapshot, file contents and commits from the worktree's git, never the network; it refuses every write and every call the snapshot cannot answer (exit 1), and each refusal is logged in scratch, counted in the cleanup line and the summary, and listed in the report. The real `gh` stays without credentials. The proof carries one github line: the snapshot's repo, time and counts; `github: none (no GitHub remote)`, where the offline gh refuses every call and the run continues; or SKIPPED under `--no-github`. If origin is on GitHub and the fetch fails (no auth, network), the run aborts before the judge with exit 67 unless `--no-github` is given. The qc brief, owned by `scripts/octo-feather-qc`, tells the judge what evidence exists (the snapshot, the read-only lane and director history) and that a criterion judged only from history says so in its why and passes only if the history shows the exact behavior. Before any fetch or judge the script also refuses a PR that is not a positive integer and an id given twice, missing from the status file or without criterion text in the spec (exit 64); once the judge has run, any exit (a failed status check or commit included) restores the status file to HEAD, so it is never left modified and uncommitted. Decided by Tom (owner), 2026-10-19.

Order in a lane, the pilot included: integrate, then `just qc` on that head (its status commit is the only change it adds), then a fresh code review of the resulting head, then the merge ask, which names the head, each criterion's QC verdict and the review verdict. A failed criterion is a blocking finding (`source: qc`) for an implementer; which later changes to the head need QC rerun is spec `#lanes-one-head` and `#gates-merge` (ADR 0007). QC and review judge adjacent heads, not one: `just qc` judges H, its status commit makes H′, and the review judges H′; before the merge ask the supervisor checks that the status commit is the only change between them. No further mechanism ties the two verdicts to one head. Decided by Tom (owner), 2026-10-19.

## Considered options

- Record QC as not run while `just qc` is a stub, and let the code reviewer's Spec pass stand in. Rejected: the Spec pass reads the diff and runs nothing, so a criterion can be claimed built without anyone having seen it work.
- Block every merge until Jev exists. Rejected: nothing could ship before Thursday.
- Let the supervisor or the implementer flip criteria to built. Rejected: the writer of the claim would be the party it judges.
- A judge from the implementer's family. Rejected: it shares the implementer's blind spots (ADR 0013's reviewer rule).

## Consequences

- Built means a fresh judge saw it pass at that head, not that Jev verified it. Jev replaces the judge behind the same recipe (docs/future.md).
- Each run leaves its own report, with the judge's raw output, the proof and the cleanup counts, in `$(octo-feather-state)/qc/<head>-<UTC stamp>-<runid>.json`; a rerun at the same head never overwrites one (finding 15).
- The sandbox needs unprivileged user namespaces (nested), util-linux `unshare` with `--map-user` and `setpriv`; CI enables user namespaces where the runner restricts them, and the qc test never skips. Its exploits (umount a mask, a nested-namespace survivor, Pi credential copies (any size, an intermediate refresh, token values) into HOME, the worktree and `.git`, a key added to `auth.json` (refused), an in-place refresh (written back), a box refresh during the run (box value kept), tracked and non-ignored writes, a judge-spawned pane) run against the fake herdr in CI and the real one on the box; the test prints which.
- Every target repo defines a `qc` recipe calling `octo-feather-qc`, as it does `integrate`, passing its arguments as exported variables, never as interpolated shell source (#30); the templates do.
