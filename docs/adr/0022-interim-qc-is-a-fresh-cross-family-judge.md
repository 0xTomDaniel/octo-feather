# `just qc` captures each declared demo deterministically and judges only stored evidence

`just qc STATUS PR ID...` (`scripts/octo-feather-qc`) is the product judge. In the lane worktree, at the integrated head, it first captures, with no model: each claimed criterion's demo, declared in the target's app-driver contract (ADR 0025), runs in the qc sandbox below, in a headless browser there when the demo declares one, and what it captured (command, exit status, output, screenshots) is appended to the target's evidence store under the head, the criterion text hash and the contract and fixture versions. It then judges from those records only: exact assertions first (the demo's own checks), then one closed question per criterion to the kit's judgment model, strictly advisory: shown labelled beside the result, read by no gate (judgment spec); a result comes only from the demo's checks or the labelled agent fallback. A criterion whose evidence is incomplete gets the result insufficient evidence, which blocks the merge ask. Only a criterion with no declared demo gets the agent fallback: a fresh qc judge from its own role (`pi-role agents/qc-judge.md -p`, ADR 0016; `openai/gpt-6.1-sol` high, read-only tools), time-capped, judging that criterion alone, its report stored as the criterion's evidence and its result labelled agent fallback. The script, never a model, then writes the status file (ADR 0021): each passed criterion becomes `built` with the lane's PR, its evidence record and the tests its demo declares; every other one stays `planned`; only that file is committed. The rules: quality spec `#qc-run`. The fallback judge's model family must differ from the implementer's, and the script refuses one that does not; it also refuses a dirty worktree, a result set that does not name exactly the claimed ids, and a run that changed the worktree. It is never part of `just check`. Decided by Tom (owner), 2026-10-19; corrected in place to deterministic capture and judgment from stored evidence, 2026-10-28, by Tom's decision of 2026-10-23 (issue #127), after the agentic judge gave different verdicts on unchanged evidence: #111, #119, #136.

Captured demos and the fallback judge have bash, so they run sandboxed by default (#33; lane #15 run 6 showed an env or PATH shim is not isolation: an explicit `herdr --session default` read the live session). `octo-feather-qc` starts `scripts/octo-feather-qc-sandbox` in two namespaces. The outer `unshare -rm` (root of a private user and mount namespace) sets the boundary up: a private `/tmp`; tmpfs over the Herdr and gh config dirs, `~/.ssh` and the cache dir, `/dev/null` over git credential files; a scratch state dir where the caller's archived lanes and director log are read-only history and live lane records (`lanes/`, `sessions/`, `director.toml`) are masked; Pi's agent dir a tmpfs with its files bound back read-only, `auth.json` and `models.json` per-run copies on the hidden run tmpfs, only where a Pi runs (a fallback judge, the advisory classify run): a declared demo runs the target's own code and its sandbox holds neither, its proof saying so (owner ruling 2026-10-29, #438); mise's state dir (`MISE_STATE_DIR`, where `mise trust` writes) an empty per-run dir on the private `/tmp`, never a copy of the caller's, whose trust entries name other repos (#428); mise offline and never installing (auto-install and the shims' system fallback off), so a tool not installed for the worktree or the kit fails the pre-run proof naming `scripts/octo-feather-mise-install DIR`, run outside the sandbox (#437); and every other repo on the box a tmpfs (#182; seen: a `--kit-ref` qa run read the future kit from sibling lane worktrees): each git repo up to 3 levels below HOME (dot-dirs aside, symlinks not followed), found at setup, but the run's kit under test and its worktree or fixture, with only what the run needs bound back on its mask (a kept path inside it, a kept tree's git common dir, read-only, and in a `--kit-ref` run the machinery the sandbox runs from the head kit: itself, `octo-feather-state`, `scripts/octo-feather-mise-install`, the offline gh's dir and the judge's command), a PATH dir inside a hidden repo swapped for the same path in the run's kit; a mask that fails aborts (exit 66), a proof line names each mask and what stays visible, and each open of a mask is recorded as a `repo` attempt (what counts, and its limit: eval-cases schema, Attempt record). Its limits: a kept worktree's git common dir keeps other branches' objects reachable through git; a repo deeper than 3 levels or under a dot-dir is not hidden. Then every other mount but `/proc` is remounted read-only (`/dev/mqueue` and `/sys` included; the judge also gets its own IPC namespace), and the lane worktree is mounted as an overlayfs over the real one, its upper and work dirs on a run tmpfs that is then masked from the judge. The judge has no persistent writable path: everything it writes, anywhere (worktree, ignored or not, `.git`, `/tmp`, cache, Herdr dir), dies with the namespace; the git common dir outside the worktree stays read-only. There is no exception, Pi's `auth.json` and `models.json` included (round 4, finding persistent-credential-copies: the original bound writable let the judge store a copied token under a new key): the judge may rewrite its per-run copies, and they are discarded with the run, never written back to the box (round 7, director ruling: the box `auth.json` is `{}` and both providers use a static `apiKey` in `models.json`, so a write-back, with its snapshot, compare and swap and Pi auth lock, bought nothing and carried the race of finding non-atomic-auth-writeback). If the box `auth.json` holds an OAuth entry (a provider entry of type `oauth` or with a refresh token field), `octo-feather-qc` prints `auth.json has OAuth credentials: a token refresh during this run is discarded` once per run, when a sandbox with copies starts, and proceeds. Residual: with OAuth tokens that rotate on refresh, a refresh during a qc run is lost, and the box's next use of the old refresh token may fail until Pi logs in again. The judge itself runs in a nested user namespace mapped to the caller's uid and gid (not root), with its own mount and PID namespace and `no_new_privs` (`unshare --map-user --map-group --mount --pid --fork --kill-child`, `setpriv --no-new-privs`): it holds no capabilities and every inherited mount is locked, so `umount` of a mask fails, also after the judge's own `unshare -rm` (round 2, finding reversible-sandbox-masks). PID 1 of that namespace is ours: it starts the one fresh per-run Herdr server (`qc-<head12>-<runid>`) inside it, so panes the judge spawns inherit the whole sandbox, pinned by a `herdr` shim that drops `--session`/`--remote`/`--machine`; no GitHub or git credentials and no parent route (`OCTO_FEATHER_PARENT`, `HERDR_*` ids and socket paths). Before the judge starts PID 1 prints one ok or FAIL line per check (no capabilities, masks locked, HOME read-only (and the kit, unless the kit is the judged worktree, as when it judges itself), worktree overlay, writable persistent paths: none (no exception), Herdr, creds, route, state, history, worktree clean), and any FAIL aborts (exit 66). After the judge exits it counts the agents the judge started (headless Pi and sandbox Herdr panes), stops and deletes the sandbox session, kills and counts every other process in the PID namespace, and exits, so the kernel kills anything left there or in a nested PID namespace (`unshare -m env -u HERDR_SESSION ...` cannot escape). Proof, cleanup record and judge stderr come back to `octo-feather-qc` over pipes, so no write fd pins a mount being remounted read-only. Credential copies are prevented by construction, not scanned for (round 3, finding persistent-credential-copies: a scan of pre and post values cannot cover an intermediate one), so the credential content scan is dropped. The read-only check survives: after the judge exits, the sandbox, outside the judge's namespaces, lists the overlay upper dir, and `octo-feather-qc` fails the run (exit 3, the paths in the report) on a new, changed or deleted tracked file or an untracked file git does not ignore; ignored outputs and `.git` writes are discarded silently, and the real worktree never changes. `--no-sandbox` is for debugging only: printed as UNSANDBOXED, it writes the report and never changes the status file. Decided by Tom (owner), 2026-10-19.

The judge gets read-only GitHub evidence (#34; lane #23 failed 8 criteria only because GitHub was absent). When the worktree's `origin` is a GitHub URL (read locally, so missing auth cannot pass for no remote), `octo-feather-qc` runs `scripts/octo-feather-qc-ghsnap` before every run, outside the sandbox and with the caller's gh auth, into fresh per-run scratch: issue, PR and workflow run lists (all states; 500, 500, 200), full views (comments, reviews, commits, files, closing issues, sub-issues, blocked-by, timeline, the head's check runs) for the 200 most recently updated issues and PRs, fetched in parallel (about 12 s for this kit's 35), and the repo, branches, labels and origin refs; older items stay list-only and are named. The snapshot is made read-only, bound read-only into the sandbox, and removed after the run. `scripts/qc-bin` goes first on the judge's PATH: its offline `gh` answers `gh issue view|list`, `gh pr view|list|diff|checks`, `gh run view|list`, `gh repo view` and `gh api` GETs (with `--json` and `-q/--jq`) from the snapshot, file contents and commits from the worktree's git, never the network; it refuses every write and every call the snapshot cannot answer (exit 1), and each refusal is logged in scratch, counted in the cleanup line and the summary, and listed in the report. The real `gh` stays without credentials. The proof carries one github line: the snapshot's repo, time and counts; `github: none (no GitHub remote)`, where the offline gh refuses every call and the run continues; or SKIPPED under `--no-github`. If origin is on GitHub and the fetch fails (no auth, network), the run aborts before the judge with exit 67 unless `--no-github` is given. The qc brief, owned by `scripts/octo-feather-qc`, tells the judge what evidence exists (the snapshot, the read-only lane and director history) and that a criterion judged only from history says so in its why and passes only if the history shows the exact behavior. Before any fetch or judge the script also refuses a PR that is not a positive integer and an id given twice, missing from the status file or without criterion text in the spec (exit 64); once the judge has run, any exit (a failed status check or commit included) restores the status file to HEAD, so it is never left modified and uncommitted. Decided by Tom (owner), 2026-10-19.

Order in a lane, the pilot included: integrate, then `just qc` and a fresh code review in parallel on that integrated head H, neither waiting for the other, then the merge ask. Both are QC: `just qc` judges the product against its criteria, the code review judges the lane's code quality; neither is QA, which judges the factory (`just qa`). `just qc`'s status commit makes H′, and the merge ask names H′, the judged head H and both verdicts. `octo-feather-lane merge-ask` fails unless H to H′ holds only qc's status commits, changing only the status files, naming any other file; a merge of main after H keeps the qc verdict only when that check proves the merge resolved no conflict and left the lane's own diff against main identical to its diff at H, and the merge ask carries the check's proof line. A failed verdict of either is a blocking finding (`source: qc` or `code-review`) for an implementer, then both run again in parallel on the new head; which later changes need QC rerun is spec `#lanes-one-head` and `#gates-merge` (ADR 0007). Decided by Tom (owner), 2026-10-19; corrected in place to parallel runs on one head, 2026-10-22 (issue #67).

## Considered options

- Keep one agentic judge that finds, runs and judges each demo. Rejected: it gave different verdicts on unchanged evidence (#111: acceptance-prompt-eval passed 4 runs, failed 1; #119: acceptance-judge-bench passed at two heads, failed at a third on the same facts; #136: one criterion read three ways across heads), and took about 8.5 minutes a run.
- Let the classifier decide or gate verdicts, at once or once calibrated. Rejected for now: no gate reads a model's answer (judgment spec); classifier-first verdicts and gating are a later decision, after a rebench (owner, 2026-10-28, issue #127).
- Record QC as not run while `just qc` is a stub, and let the code reviewer's Spec pass stand in. Rejected: the Spec pass reads the diff and runs nothing, so a criterion can be claimed built without anyone having seen it work.
- Block every merge until Jev exists. Rejected: nothing could ship before Thursday.
- Let the supervisor or the implementer flip criteria to built. Rejected: the writer of the claim would be the party it judges.
- A judge from the implementer's family. Rejected: it shares the implementer's blind spots (ADR 0013's reviewer rule).

## Consequences

- Built means a demo captured at that head passed its checks, or, labelled, the fallback judge passed it; its evidence goes stale when its code or text changes (quality spec `#qc-stale`).
- Each run leaves its own report, with the judge's raw output, the proof and the cleanup counts, in `$(octo-feather-state)/qc/<head>-<UTC stamp>-<runid>.json`; a rerun at the same head never overwrites one (finding 15).
- The sandbox needs unprivileged user namespaces (nested), util-linux `unshare` with `--map-user` and `setpriv`; CI enables user namespaces where the runner restricts them, and the qc test never skips. Its exploits (umount a mask, a nested-namespace survivor, Pi credential copies (any size, an intermediate refresh, token values) into HOME, the worktree and `.git`, the judge rewriting its `auth.json` and `models.json` copies and an in-place refresh (both discarded: the box files stay byte-identical, no OAuth warning), OAuth credentials on the box (one warning line, the run proceeds, no credential value printed), tracked and non-ignored writes, a judge-spawned pane) run against the fake herdr in CI and the real one on the box; the test prints which.
- Every target repo defines a `qc` recipe calling `octo-feather-qc`, as it does `integrate`, passing its arguments as exported variables, never as interpolated shell source (#30); the templates do.
