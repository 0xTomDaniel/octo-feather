# b-exact-or-proxy: labelled set (lane gh119, #119)

Question: Does this check test its rule itself, as stated where the rule is owned (a spec criterion, an ADR or a recorded owner ruling, never the check's own text), or a stand-in that only correlates with the rule?

Labels: `exact` (the check tests the owned rule itself; any case it lets through, or wrongly refuses, is a defect to fix, not a different label), `proxy` (the check tests a stand-in that only correlates with the owned rule, such as code tokens for coupling, words for reachability or a pattern over prose for intent)

State shape: the rule as stated where it is owned, as a leading line Rule (owned): "<quote>" (<pointer>), then what the check reads: its path and a code excerpt trimmed from its source at a pinned commit, which may include the check's own docstring, comments and error text

Source: the director-owned final set /tmp/gh119/labels/b-exact-or-proxy (director-checked and owned, 2026-10-23), copied in as is: question.json and cases.json byte-identical, each reference entry its label, reason and source unchanged plus `labelled_by: director` and, for the two final flips, a one-line `relabel`. Not part of this suite: the set's DEFECTS.md (its D1 to D21 defect list, cited by reasons) and held/ (gh108-check-evals-leaks, below).

Real history: all 31 cases are checks and graders the factory actually committed (sources pin path, lines and commit), each with the rule quoted from where it is owned; none constructed.

Split: as the director-owned set fixed it. The set's first draft (b-fact-or-meaning) chose held-out as every third case per label in source order, starting with the first, before patterns were examined; relabels since never moved a split, so the per-label split no longer follows that rule exactly.
